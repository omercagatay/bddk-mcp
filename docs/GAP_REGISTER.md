### CUR-007 closure boundary and storage evidence

H2-02A is now implemented as additive retained staging, not rollback. It
separates physical generation, governed release, seal, and activation
identities; captures 17 typed generation-qualified relations under the schema
and corpus mutation locks; reproduces the exact v5 state hash; and rejects
member, inventory, seal, and binding mutation after sealing. Existing v5
releases are labelled `legacy_v5_unretained` rather than backfilled with
evidence that does not exist. Serving and the active identity remain unchanged.
The physical generation and its single seal are exact-state/profile-derived;
multiple governed releases over that same pair retain separate release
bindings to the shared physical target. Release count therefore must not be
used as physical-generation count.

The CLI emits privacy-safe, catalog-reconciled heap/main, auxiliary, TOAST,
index, logical, and total sizes. When available, its best-effort WAL number
covers the observed cluster interval around the transaction and is explicitly
`observed_cluster_interval_not_exclusive`; it is not exact generation
attribution; otherwise WAL remains `not_measured`. `backup_growth_status`
remains `not_measured` until a controlled
DBA/bank backup is run. Bank retention count and capacity authorization also
remain open, so H2-02A acceptance is partial even though the repository
mechanism exists. Capacity approval must measure unique physical generations;
governance retention must still preserve every per-release binding.

V7 retains the exact fields already present in PostgreSQL, including a stored
`documents.pdf_blob` where one exists. It does not acquire or retain external
authoritative source files beyond those database fields; in particular,
`regulatory_source_blobs` remains a content-identity record rather than an
external artifact-byte store. This slice must not be described as complete
source authenticity or evidence-pack preservation.

H2-02B closes the gap only when every document, section, vector, decision-cache,
Citation, legal-status, and process-cache read is bound to one retained
generation, and activation/reactivation is one append-only event authorized by a
separately scoped signed corpus policy. That policy must bind the current head,
exact target, validity/revocation, action, reason/change-record hash, and approving
roles; N-01's verifier primitives may be reused, but an evaluation policy does
not implicitly authorize a corpus downgrade.

The tracked artifacts total 24,377,264 bytes (23.25 MiB): 8,769,689 bytes of
documents, 15,454,535 bytes of chunks, and 153,040 bytes of decision-cache rows
(**seed_data/corpus_scope.yml:30-45**). Raw 768-dimensional float32 embeddings
add 24.28 MiB for 8,286 chunks or 28.34 MiB for the current 9,675-chunk
regeneration (**docs/CORPUS_GOVERNANCE.md:96-98;
bddk_mcp/migrations/v0001_core.py:189-212**). The resulting greater-than 51.6 MiB raw lower bound excludes
sections, tuple/MVCC and TOAST overhead, duplicated text/`tsvector`, GIN/HNSW
indexes, WAL, backups, and original source bytes. CUR-008 leaves the retention
window unapproved, so unique generation count and capacity require H2-02A measurements
plus the approved N-03 objectives; this estimate is not a storage target.

## Why each High finding is High

### MCP-001

This is the documented primary local integration, not an obscure optional path. It starts a valid-looking server with no usable tools and blocks the project's core purpose.

### SEC-001 and SEC-002

The HTTP listener is network-bound without repository-defined identity or Origin/Host protection. If operator mode is enabled, unauthenticated callers gain database-changing and expensive operations. The default-off operator flag prevents a Critical rating but is not a safe remote control.

### PRIV-001

The intended enterprise workflows include internal audit and compliance investigations. Logging their query/result text to platform logs creates a realistic confidentiality exposure even when regulatory documents themselves are public.

### DB-001

The public serving identity can own/evolve schema and write the corpus. That materially enlarges the impact of an MCP, dependency, or upstream-content compromise and makes least-privilege deployment impossible.

### DATA-001 and DATA-002

These can silently serve an older regulation: startup can replace fresher content with bundled seed, and a partial reindex can leave stale chunks preferred by retrieval. Regulatory correctness depends on preventing that state.

### ING-001

Exact article retrieval is an advertised core workflow. A fresh supported bootstrap can contain the document but return no section, so the normal deployment path is functionally incomplete.

### ING-002

Capital, liquidity, IRB, IRRBB, and TFRS 9 conclusions may turn on a formula sign, denominator, threshold, or table cell. The current extraction evidence is insufficient for calculation-level reliance.

### QUAL-001 and QUAL-002

The repository has explicitly identified bad documents but runtime can label them clean or omit the warning. A known defect that is invisible at retrieval time can become cited audit evidence.

### RET-001

Without legal versions and temporal status, the system cannot answer the central legal question: which provision applied. Drafts, old texts, and repealed texts can look equally retrievable.

### RET-002

Regulatory obligations often attach to a precise subparagraph/item. A lossy identifier cannot support unambiguous citations, amendment mapping, or audit control lineage.

### CIT-001

Character windows labeled as pages produce false precision. A reviewer cannot reconstruct the cited provision from an immutable official artifact, undermining traceability.

### EVAL-001 and EVAL-002

The live phase does not use the server's MCP route and can treat transport errors as results. The tiny, weakly sourced data and silent grader fallback can reward hallucinated/uncited answers. Published model comparisons would be misleading.

### LIC-001

The existing license grants the commercial rights the product objective seeks to restrict. This is a direct strategic/legal conflict that code changes cannot solve retroactively.

### OPS-005

OpenShift AI is now the confirmed bank deployment target, no external endpoint protection is currently confirmed, and the repository contains no target-platform security or operational contract. Carrying the current all-interface, unauthenticated, broad-DB-role defaults into the bank environment would create a direct deployment risk, so this is High rather than a generic documentation enhancement.

## Severity calibration notes

- No arbitrary SQL tool or confirmed SQL injection was found, so SQL injection is not a High/Critical issue in the current surface.
- SSRF and archive risks are Medium because they require the ingestion/operator path or a compromised upstream and no exploit was demonstrated.
- Tenant isolation is Medium today because private multi-tenant serving is not implemented; it becomes High before such a deployment.
- Compose defaults are Medium because they are presented primarily as local development; they become High if copied to a shared/remote host.
- Missing resources/prompts are not registered as a gap: they are optional MCP features and should be added only for measured product value.
